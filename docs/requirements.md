# Ant-Captcha 需求文档（Requirements）

> 版本：v0.5（评审稿） · 状态：待评审
> 定位：**自托管打码平台服务**（私有云码）——提供 HTTP 打码 API，媒体进、答案出，基于 ddddocr 底座 + 百炼外部能力。

---

## 1. 项目概述

### 1.1 定位

Ant-Captcha 是一套**可自托管的打码平台服务**：通过 HTTP API 接收验证码媒体（图片 / 音频 / 语义描述），返回结构化答案（文本 / 坐标 / 选择）。形态对标行业打码平台（如云码 jfbym、2Captcha），但**完全自托管、自控成本、可定制**。

### 1.2 边界（最高优先级约束）

- 核心**只做"媒体 → 答案"**，不探索界面、不操作浏览器、不管理页面状态；
- 取图、执行、校验由**调用方**负责（RPA 流程、浏览器自动化、任意 HTTP 客户端）；
- 调用方与平台之间**只隔一层 HTTP 协议**，语言无关、框架无关。

### 1.3 目标用户

| 用户 | 角色 |
|---|---|
| RPA 开发者 | 主用户：通过 HTTP API 接入自家 RPA / 浏览器自动化流程 |
| 平台运维者 | 部署、监控、扩容打码服务 |
| 算法工程师 | 为特定验证码训练模型，注册为定制类型（Solver） |

### 1.4 设计目标

| # | 目标 | 验收口径 |
|---|---|---|
| G1 | 协议友好 | 任意语言 curl 一行可调；协议参数对齐行业惯例，云码用户可零成本迁移 |
| G2 | 开箱即用 | Docker 一键起服务；内置常用验证码类型（数英 / 滑块 / 点选 / 语音） |
| G3 | 定制能力 | 针对具体验证码注册定制类型（自定义 ONNX 模型），与内置类型同接口 |
| G4 | 多后端可插拔 | 本地推理 / 百炼外部 API 可配置切换与降级，业务零改动 |
| G5 | 自托管可控 | 数据不出域、成本可控、密钥自管 |
| G6 | 合规优先 | 内置合法使用边界与滥用防护 |

### 1.5 非目标（明确不做）

| 条目 | 说明 |
|---|---|
| 浏览器自动化 | 不做页面级 API；Playwright/Selenium 仅为参考集成示例 |
| 第三方打码平台接入 | 不代理 2Captcha / 云码等外部打码服务（我们是服务提供方，不是代理方） |
| reCAPTCHA 凭证类 | 浏览器内凭证型（v2/v3）不在首发范围，见开放问题 |
| 通用模型训练平台 | 训练是独立工作流，仓库只提供文档与脚本 |
| 100% 通过率承诺 | 验证码本质是概率问题 |

## 2. 术语表

| 术语 | 定义 |
|---|---|
| 打码（CAPTCHA Solving） | 接收验证码媒体，产出答案的过程 |
| Solver | 针对**某一类具体验证码**的求解器封装：识别 + 预处理 + 降级策略；对外表现为一个 **type 代码** |
| 定制类型（Custom Type） | 用户针对特定验证码注册的 Solver，动态分配 type 代码（行业惯例，如云码"定制-xxx"） |
| 底座（Base） | ddddocr 通用能力：OCR / 目标检测(det) / 滑块缺口 / 自定义 ONNX 导入 |
| Provider | 能力后端：本地推理服务 / 百炼外部 API；对 Solver 层同构 |
| 百炼（Bailian） | 阿里云百炼：唯一外部 AI 供应商（VLM + ASR） |
| 契约（Contract） | 编排层（Node）与自建推理服务（Python）之间的 OpenAPI 接口定义 |
| 媒体（Media） | Solver 输入：image / audio / description |
| 答案（Answer） | Solver 输出：text / coordinates / choice + 置信度 |
| 调用方（Caller） | 消费打码 API 的一方：RPA 流程、浏览器脚本、CLI、任意 HTTP 客户端 |

## 3. 能力模型：Solver = 定制类型

平台所有识别能力统一抽象为 **Solver**，每个 Solver 注册后获得一个 **type 代码**，调用方只需传 type 即可：

```
┌─ 调用方（任意语言）─────────────────────────┐
│  POST /api/solve  { token, type, media... } │
└──────────────────┬──────────────────────────┘
                   │ 媒体进（image / audio / description）
                   ▼
┌─ Ant-Captcha（打码平台服务）─────────────────┐
│  type 路由 → Solver（识别 + 降级链）→ Answer │
│  内置：数英 OCR / 中文字符 / 计算题 / 滑块 /  │
│        点选(det+VLM) / 语音(ASR)             │
│  定制：用户注册的 ONNX 模型 → 新 type 代码    │
└──────────────────┬──────────────────────────┘
                   │ 答案出（text / coordinates / choice）
                   ▼
         调用方自行执行（拖动 / 点击 / 输入 / 校验）
```

**输入输出契约（冻结，不可含浏览器类型）：**

| Solver 类型 | 输入 | 输出 |
|---|---|---|
| 数英 / 中文 / 计算题 | image | text + 置信度 |
| 滑块缺口 | image(背景) + image(滑块) | coordinates(距离/坐标) + 置信度 |
| 点选（det） | image | coordinates[] |
| 点选（语义 VLM） | image + description(extra) | coordinates / choice |
| 语音（ASR） | audio | text + 置信度 |
| 自定义 ONNX | image | text / coordinates（按模型） |

## 5. API 协议规范（核心交付）

> 协议对齐行业惯例（参数名与云码兼容），HTTP 仅 POST，JSON / form-urlencoded 均可。

### 5.1 通用识别端点

```
POST /api/solve
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| token | string | 是 | 平台密钥（服务端签发） |
| type | string | 是 | 验证码类型代码（见 5.4） |
| image | string | 视类型 | 图片 base64 |
| slide_image | string | 滑块 | 小图（滑块）base64 |
| background_image | string | 滑块 | 背景图（需还原）base64 |
| extra | string | 点选 | 语义描述，如"请点击包含红绿灯的图片" |
| audio | string | 语音 | 音频 base64 |

### 5.2 响应结构

```json
{
  "code": 10000,
  "msg": "请求成功",
  "data": {
    "code": 200,
    "data": "答案文本 | 坐标 x,y,x,y | 序号",
    "time": 312,
    "provider": "local | bailian",
    "confidence": 0.96,
    "uniqueCode": "8f3a...",
    "meta": {}
  }
}
```

### 5.3 错误码

| code | 说明 |
|---|---|
| 10000 | 识别成功 |
| 10001 | 参数错误 |
| 10002 | 配额不足（可选计费后启用） |
| 10003 | 无此权限（token 无效/吊销） |
| 10004 | 无此验证类型 |
| 10005 | 网络拥塞 / 服务繁忙 |
| 10006 | 数据包过载（图片过大） |
| 10007 | 服务繁忙，请稍后重试 |
| 10008 | 内部错误 |
| 10009 | 结果准备中（异步扩展位） |

### 5.4 type 代码表（Solver 注册表）

| 区间 | 类型 | 示例 |
|---|---|---|
| 1xxx | 图形文本 | 1001 数英1-4位 · 1002 数英5-8位 · 1003 中文字符 · 1004 计算题 |
| 2xxx | 滑块 | 2001 滑块缺口 |
| 3xxx | 点选 | 3001 文字点选(det) · 3002 语义点选(VLM, extra) |
| 4xxx | 语音 | 4001 语音验证码(ASR) |
| 9xxx | 定制 | 9001+ 用户注册的定制类型（动态分配） |

> 定制类型是平台核心差异化：用户训练针对特定验证码的 ONNX 模型后注册，获得专属 type，复用同一协议。

## 6. 功能需求

### 6.1 平台服务层（Node.js + Cordis）

| # | 需求 | 验收要点 |
|---|---|---|
| FR-1 | HTTP 打码 API | `POST /api/solve` 按 5.x 协议实现；JSON 与 form-urlencoded 均支持 |
| FR-2 | token 鉴权 | 服务端签发/吊销；无效 token 返回 10003；日志不记录 token |
| FR-3 | type 路由 | type → Solver 精确路由；未知 type 返回 10004 |
| FR-4 | 插件化架构 | 核心能力均以 Cordis 插件提供，可独立挂载/卸载，卸载无残留 |
| FR-5 | 配置驱动 | 全部行为经 `cordis.yml` 组合，无硬编码 |
| FR-6 | 结构化日志 | 每请求耗时、type、provider、成败可追溯（含请求 ID） |
| FR-7 | 请求 ID 贯穿 | 同一次求解在平台与推理服务两侧共享请求 ID |

### 6.2 Solver 层

| # | 需求 | 验收要点 |
|---|---|---|
| FR-8 | 声明式 Solver 定义 | name/type/模型/字符集/降级链全声明化 |
| FR-9 | 内置 Solver | 数英、中文、计算题、滑块、点选(det)、点选(VLM)、语音 7 类开箱即用 |
| FR-10 | 定制类型注册 | 自定义 ONNX + 字符集导入；注册后自动分配 9xxx type 代码，与内置同接口 |
| FR-11 | Solver 版本化 | 同名多版本可指定/回退；切换不中断服务 |
| FR-12 | 预处理/后处理管线 | 图片缩放/去噪/颜色过滤可配置；答案规范化（waterfall 事件） |

### 6.3 Provider 层

| # | 需求 | 验收要点 |
|---|---|---|
| FR-13 | 本地推理 provider | 调自建推理服务（FastAPI + ddddocr），契约见 6.5 |
| FR-14 | 百炼 provider | VLM（点选语义）+ ASR（语音）；AK 环境变量注入，不入库不进日志 |
| FR-15 | 统一 provider 抽象 | 本地/百炼对 Solver 同构；新增 provider 不改 Solver 代码 |
| FR-16 | 降级链 | Solver 级配置如 `[local, bailian]`；同媒体重试不重新取图 |
| FR-17 | 重试与容错 | 重试次数/间隔/退避可配；单次失败返回可识别错误码 |

### 6.4 自建推理服务（Python FastAPI + ddddocr）

| # | 需求 | 验收要点 |
|---|---|---|
| FR-18 | OCR 端点 | image → text（数英/中文/特殊字符；beta 模型可选） |
| FR-19 | det 端点 | image → 目标坐标列表（点选支撑） |
| FR-20 | 滑块缺口端点 | bg+fg → 缺口坐标（边缘匹配 / 图像差异双算法可选） |
| FR-21 | 自定义 ONNX 推理端点 | 按注册模型推理，返回 text/坐标 |
| FR-22 | 健康与就绪探针 | `/healthz`、`/readyz`；模型加载状态可查 |
| FR-23 | 并发与队列 | 并发请求、排队、超时可配 |
| FR-24 | CPU/GPU 自适应 | 启动探测硬件，选择推理后端 |

### 6.5 契约层（Contracts）

| # | 需求 | 验收要点 |
|---|---|---|
| FR-25 | OpenAPI 契约驱动 | 契约唯一来源 `contracts/`；Node 端生成类型化 client；Python 端校验请求/响应 |
| FR-26 | 契约版本化 | 破坏性变更升版本；v1 冻结后不静默改语义 |
| FR-27 | CI 契约校验 | 契约与两端实现不一致禁止合并 |

### 6.6 工程化

| # | 需求 | 验收要点 |
|---|---|---|
| FR-28 | monorepo | `apps/api-server` + `services/model-server` + `contracts/` + `examples/`；pnpm 与 uv 独立 lockfile |
| FR-29 | Docker | 平台镜像 + 推理镜像（含 GPU 变体）；`docker compose up` 一键起全栈 |
| FR-30 | CI 按路径分流 | 改 Python 不触发 Node 构建；契约变更触发全量校验 |
| FR-31 | 测试 | 单元（两端）+ 契约测试 + 集成测试（mock 验证码图直测 API） |
| FR-32 | 文档 | README、本文档、架构文档、ADR、快速上手 |
| FR-33 | 版本与发布 | 语义化版本；两端独立发版 |

## 7. 非功能需求

| # | 需求 | 指标 |
|---|---|---|
| NFR-1 | 性能 | 底座 OCR P95 ≤ 1s；滑块缺口 P95 ≤ 2s；≥ 10 并发 |
| NFR-2 | 可用性 | 百炼故障自动降级本地；平台无状态可多副本 |
| NFR-3 | 安全 | AK/token 环境变量注入；推理服务默认内网 + 可选鉴权；日志脱敏 |
| NFR-4 | 合规 | 合法使用声明；日志不含凭据/个人数据 |
| NFR-5 | 可扩展性 | 新验证码类型 = 注册新 Solver（新 type 代码）；新能力 = 新 provider |
| NFR-6 | 成本可控 | 百炼配额/熔断/预算告警；平台侧调用计数 |
| NFR-7 | 可观测性 | 请求 ID 贯穿；耗时/成功率/type 命中/provider 命中率可导出（Prometheus 格式） |
| NFR-8 | 兼容性 | Node ≥ 20 LTS；Python ≥ 3.11（ddddocr 上限 3.12）；协议无语言依赖 |
